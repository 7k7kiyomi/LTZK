# 图层关系配置列宽与横向滚动修复设计

## 背景与根因

质检任务管理中的图层关系配置窗口由外部质检插件创建 `QTreeWidget`。该表格包含标准图层、gdb 图层、实际图层、实际注记图层、对应注记层和图例字段六列，其中前三个映射列嵌入了 `QComboBox`。窗口初次加载时列宽过窄，组合框的显示区域被下拉箭头和边距占用，已选择的图层名称无法显示；用户拖动列分隔线后触发布局重算，因此内容重新出现。

现有宿主程序已经通过 `treeWidget_csv` 识别这个表格，并统一处理嵌入式控件，但没有为该表格设置稳定的列宽和横向滚动策略。问题不是 CSV 匹配数据缺失，也不应通过隐藏或清空单元格文字来处理。

## 目标与范围

- 仅针对对象名为 `treeWidget_csv` 且列数为六列的图层关系表设置布局。
- 在首次显示和后续布局请求后，保证 gdb 图层、实际图层、实际注记图层的组合框具有足够的显示宽度。
- 允许表格在窗口宽度不足时出现横向滚动条，保留用户手动拖动列宽的能力。
- 保留现有的下拉框文字、箭头、嵌入控件代理和三套主题处理逻辑。
- 不修改插件 DLL、CSV 解析、图层匹配和保存格式。

## 方案

在宿主程序中增加一个小范围的图层关系表列宽整理函数，并从现有的插件表格嵌入控件安装流程调用：

1. 查找插件窗口中的 `QTreeWidget#treeWidget_csv`。
2. 关闭最后一列强制拉伸，设置表头为可交互调整，避免初始 `Stretch` 把映射列压缩。
3. 设置六列的最小可读宽度：标准图层 105、gdb 图层 150、实际图层 180、实际注记图层 245、对应注记层 120、图例字段 160 像素。
4. 设置 `Qt::ScrollBarAsNeeded`，当六列总宽度超过视口时由 Qt 提供横向滚动。
5. 使用 `qMax(现有宽度, 目标最小宽度)`，不覆盖用户已经手动设置的更宽列；函数可重复调用且不会不断扩大列宽。

该方案把修复放在宿主已掌握的表格初始化/布局入口，既能覆盖插件创建完成后的初次显示，也不会依赖用户拖动分隔线来触发刷新。

## 兼容性与边界

- 如果表格不存在、列数不足或窗口不是目标插件窗口，不执行任何列宽修改。
- 通过 `Interactive` 保持列宽可拖动；横向滚动条只在必要时出现。
- 只设置最小宽度，不改变单元格当前值、选项顺序或信号连接。
- 现有 `polishDrawingLayoutTreeEmbeddedCombos` 的文字保留逻辑不变。

## 验证

- 增加源码级回归脚本，检查目标表格识别、六列宽度、`Interactive` 表头模式和横向滚动策略。
- 先运行回归脚本确认旧代码缺少该行为，再实现最小修改并重新运行确认通过。
- 运行现有的图层关系下拉框、嵌入控件和插件窗口样式回归脚本。
- 若本机具备 Qt/Visual Studio 依赖，执行 x64 Release 构建；若构建环境不可用，单独记录环境限制。
