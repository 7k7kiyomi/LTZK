# 数据列表数据库/本地数据互斥显示设计

**日期：** 2026-09-11  
**范围：** `DataCatalogWidget` 中“数据库数据”和“本地数据”两个区域的标题栏交互

## 1. 目标

调整“数据列表”页面的两个数据源区域：

- 首次打开时，数据库数据内容和本地数据内容都显示。
- 点击“数据库数据”标题栏后，隐藏本地数据内容，仅保留数据库数据内容。
- 点击“本地数据”标题栏后，隐藏数据库数据内容，仅保留本地数据内容。
- 两个标题栏始终保留，作为互相切换的入口。
- 点击当前已经显示的数据源标题栏时保持当前状态，不把当前内容隐藏。

刷新数据库、连接/断开本地文件夹、刷新本地数据等标题栏按钮继续执行原有操作，不承担区域切换职责。

## 2. 当前实现上下文

`DataCatalogWidget::buildUi()` 当前使用一个垂直 `QSplitter`，其中包含：

- `databaseCatalogSection`：标题栏、数据库树和数据库刷新按钮；
- `localCatalogSection`：标题栏、本地状态标签、本地数据树以及连接/断开/刷新按钮。

标题栏由匿名命名空间中的 `createSectionHeader()` 创建，目前标题是普通 `QLabel`，因此没有点击信号。两个数据树、数据库模型、本地 QGIS 浏览模型和现有右键/双击逻辑均已稳定工作，本次不改变这些数据流。

## 3. 设计方案

### 3.1 标题栏

将标题栏中的普通标题标签改为可点击的标题按钮，保留现有标题栏 `QFrame`、布局、操作按钮和样式属性：

- 标题按钮占据标题栏剩余宽度，显示“数据库数据”或“本地数据”；
- 标题按钮使用自动扩展的尺寸策略和指针样式，视觉上仍表现为标题栏标题；
- 标题栏右侧的刷新、连接、断开按钮继续作为独立控件；
- 标题按钮点击只触发数据源区域选择，不影响右侧操作按钮。

### 3.2 内容容器

在两个现有 section 内保留标题栏，并为非标题内容增加独立的内容容器：

- 数据库内容容器包含 `m_databaseTree`；
- 本地内容容器包含 `m_localStatusLabel` 和 `m_localTree`；
- 标题栏不属于可隐藏内容，因此无论当前选择哪一侧，两个标题栏都可见；
- 数据树、状态标签和模型对象不销毁、不重建，只切换内容容器的可见性。

### 3.3 互斥显示

在 `buildUi()` 中建立一个局部的区域选择处理器：

1. 初始不调用选择处理器，保持两个内容容器可见，并沿用当前 splitter 的默认尺寸。
2. 点击数据库标题按钮时显示数据库内容容器、隐藏本地内容容器。
3. 点击本地标题按钮时隐藏数据库内容容器、显示本地内容容器。
4. 点击已经显示的一侧时重复设置同样的可见状态，不产生“两个内容都隐藏”的状态。
5. 内容容器切换后重新分配 `QSplitter` 尺寸：可见内容占据剩余空间，隐藏侧只保留标题栏所需高度；重新切换时恢复为可用的双区域布局。

标题栏按钮仍然位于各自 section 的顶部，因此隐藏一侧的数据内容后，用户仍可以点击该侧标题恢复显示。

## 4. 数据流与边界

- `refreshDatabaseData()`、`refreshLocalFolders()`、`connectLocalFolder()`、`disconnectSelectedLocalFolder()` 的业务实现不变。
- `QStandardItemModel`、`QgsBrowserGuiModel`、代理模型和树视图实例不因切换而清空或销毁。
- 区域切换只影响 QWidget 可见性和 splitter 布局，不改变当前选中项、已勾选项、展开状态、已连接文件夹或数据库缓存。
- 右键菜单、双击加载、数据裁剪、导入、导出和批量操作继续从原有树视图触发。
- 初始双显示行为保持现状，避免改变首次打开数据列表时的用户习惯。

## 5. 错误处理与兼容性

- 如果任一内容容器或 splitter 尚未创建，切换处理器直接返回，不影响数据目录初始化。
- 区域切换不触发数据库连接，也不触发本地目录刷新，因此不会引入新的外部错误路径。
- 不修改数据库查询、本地 QGIS 浏览模型或工作区模块可见性逻辑。
- 继续沿用五套主题对 `catalogSectionHeader`、`catalogSectionTitle`、数据树和工具按钮的现有样式；标题按钮增加局部属性/对象名时，不覆盖现有主题规则。

## 6. 测试与验收

新增或扩展静态回归脚本 `tests/verify_workspace_data_catalog.ps1`，检查：

- 两个标题栏都创建可点击标题控件；
- 数据库和本地标题点击分别绑定到互斥显示逻辑；
- 两个内容容器独立存在，且标题栏不被隐藏；
- 初始内容容器保持可见；
- splitter 在切换后重新分配尺寸；
- 现有数据库树、本地树及刷新/连接按钮仍然存在。

验证步骤：

1. 先运行静态回归脚本，确认新行为检查在实现前能够失败；
2. 完成最小实现后重新运行脚本，确认新增断言和原有数据列表断言均通过；
3. 构建 `x64|Release`，确认 `DataCatalogWidget.cpp` 编译通过；
4. 启动 Release 程序进行冒烟检查，验证两个标题栏可切换且标题栏保持可见。

## 7. 非目标

- 不改动数据库目录查询、数据库登录、PostGIS 元数据读取或本地数据加载逻辑。
- 不修改工作区“数据列表”页签在业务模块之间的可见性策略。
- 不引入新的第三方控件或新的持久化配置。
- 不把两个数据源合并到同一模型或同一棵树中。
