# 本地数据与数据库成果目录右键菜单一致化设计

## 目标

让数据列表中的本地数据节点使用当前数据库成果目录节点的右键菜单内容和统一分发入口，同时保持数据库成果目录既有行为不变，也不修改质检任务管理中的导出逻辑。

## 根因

`DataCatalogWidget::showDatabaseContextMenu()` 和 `showLocalContextMenu()` 都调用 `populateContextMenu()`，但 `populateContextMenu()` 的成果目录分支限定了 `CatalogSource::Database`。数据库成果目录/成果节点因此显示专用菜单，本地目录/图层节点则继续显示旧的通用菜单。

## 设计

1. 抽取 `populateProductContextMenu()` 作为数据库成果目录菜单和本地数据菜单的共同构建器。
2. 用 `isProductMenuContext()`、`isProductMenuDirectory()` 区分数据库成果目录/成果节点与本地目录/图层节点，但两类节点使用完全相同的菜单文字、顺序和分隔线。
3. 保留数据库分支的 `m_productOperationCallback`、数据库目录勾选同步、数据导入回调和现有 ID 参数不变。
4. 本地分支通过适配器复用本地 URI、勾选状态、导入、地图加载、导出和 Favorites 显示别名逻辑；不向数据库操作回调伪造目录 ID 或成果 ID。
5. 本地不具备安全等价实现的数据库专属操作（范围导出、按制图导出、添加到主题、新建/删除数据库目录）仍显示在同一菜单中，但按实际能力禁用；启用的本地操作统一经过 `dispatchProductOperation()` 的本地分支。
6. 本地目录的“勾选本节点下全部成果/取消勾选本节点下全部成果”只操作当前本地树节点及已加载子节点，状态继续由现有 `m_checkedLocalPaths` 保存。

## 菜单契约

目录节点必须按以下顺序显示：

```text
新建目录
删除目录
重命名
---
勾选本节点下全部成果
取消勾选本节点下全部成果
---
导入数据
导出所选数据
按范围导出
按制图导出
---
添加到地图
添加到主题
```

成果/图层节点必须按以下顺序显示：

```text
导出所选数据
按范围导出
按制图导出
---
添加到地图
添加到主题
```

## 非目标

- 不修改质检任务管理的任何导出代码或导出目录组织逻辑。
- 不把本地文件注册、写入或复制到数据库成果目录。
- 不修改数据库成果目录已有的回调协议、操作 ID、产品 ID 和连接参数。
- 不修改本地文件名、目录名或删除本地文件。

## 验收标准

- 本地目录和本地图层右键菜单与对应数据库成果目录/成果节点的文字、顺序、分隔线完全一致。
- 本地和数据库菜单均由 `populateProductContextMenu()` 构建。
- 数据库操作仍走既有 `m_productOperationCallback`/`m_dataImportCallback`。
- 本地地图加载、导入、显示别名和导出分别走现有本地 URI/文件回调，不产生数据库 ID。
- 回归检查通过，`LTZK.vcxproj` Release x64 构建通过。
