# LTZK 1920×1080 统一设计画布修正设计

## 背景

现有全局分辨率改造没有达到“不同屏幕保持 1920×1080 基准视觉比例”的目标。根因是 Qt/Windows DPI 缩放、平台全局缩放、首页剩余空间自适应和卡片内部响应式缩放同时生效；部分自绘字体和几何量又绕开全局比例。日志 Dock 等可变区域还会改变主页布局，导致卡片横向过大、纵向拥挤和图标裁切。

本设计只修改 LTZK 平台侧代码。`map_product_manager`、`map_product_manager_tools` 及其他业务插件源码不在范围内。

## 目标

- 以 Windows 1920×1080 下用户确认的界面为唯一视觉基准。
- 任意屏幕分辨率和 Windows DPI 下，平台字体、图标、控件、间距和自绘元素保持同一等比关系。
- 非 16:9 屏幕采用等比缩放和居中留白，不横向或纵向拉伸。
- 同一个视觉尺寸只应用一次 LTZK 比例；Windows DPI 仍由 Qt 负责映射到物理像素。
- 首页日志 Dock 显示或隐藏时，不重新放大卡片；空间不足时整体画布继续等比缩小或被稳定留白约束。

## 方案比较

### 方案 A：统一设计画布与单一比例（采用）

以 1920×1080 为设计坐标，计算一次 `scale = min(logicalWidth / 1920, logicalHeight / 1080)`。所有平台视觉量从基准值乘该比例，宽高比不同产生的剩余空间居中留白。删除组件自身代表屏幕分辨率的比例计算。

优点是符合用户目标、DPI 责任清晰、可以连续支持任意分辨率。代价是需要清理现有局部缩放，并为平台自绘控件补齐统一比例。

### 方案 B：保留各页面响应式布局

继续由每个页面根据剩余空间计算卡片和字体。实现改动较小，但 Dock、窗口客户区和不同宽高比会持续改变主页构图，无法保证与 1920×1080 一致，因此不采用。

### 方案 C：把整个界面渲染成纹理后缩放

可以获得接近截图级一致性，但 Qt 原生控件、QGIS 地图画布、输入焦点、弹窗和无障碍交互都会复杂化，并可能产生模糊，因此不采用。

## 缩放模型

### Qt 与 Windows DPI

Qt 高 DPI 支持在 `QgsApplication` 创建前启用。`QScreen::geometry()` 提供 Qt 逻辑尺寸；LTZK 使用逻辑尺寸计算应用比例。Qt 的设备像素比只负责把逻辑坐标映射到物理像素，LTZK 不再额外乘 `devicePixelRatio`。

### 唯一比例

```text
screenScale = min(logicalScreenWidth / 1920,
                  logicalScreenHeight / 1080)
```

有效正数直接使用，不设置会破坏严格等比关系的 `0.70`、`0.65` 等下限。屏幕信息无效时降级为 `1.0`。

### 留白

```text
canvasWidth  = 1920 × screenScale
canvasHeight = 1080 × screenScale
offsetX = (availableWidth  - canvasWidth)  / 2
offsetY = (availableHeight - canvasHeight) / 2
```

平台首页与平台自有全屏页面放在居中的设计画布区域。剩余区域保持主题背景。地图、树、表格等内容区可以在画布内部继续使用 `Expanding`，但不改变字体、按钮和工具栏的全局比例。

## 首页修正

- 删除 `adaptiveHomeModuleCardSize()` 对容器剩余空间的独立比例计算。
- 删除 `responsiveScaleForSize()` 和 `cardScaledInt()` 对字体、边距、图标的第二次动态缩放。
- 将用户确认的 1920×1080 首页效果固化为明确的卡片基准尺寸和基准字体尺寸，再统一乘 `screenScale`。
- 卡片宽高同时固定到缩放后的基准尺寸，防止布局只限制宽度却压缩高度。
- 标题、自绘装饰、阴影、圆角、线宽、图标和文字矩形均使用同一比例。
- 网格间距、功能按钮、底部间距和页脚使用同一比例；不再根据 Dock 的剩余高度重新放大卡片。

## 日志 Dock 与状态差异

日志 Dock 属于平台外壳。主页视觉对比时必须保持相同显示状态。实现中 Dock 的显示只减少可用客户区，不改变组件自身比例；若剩余区域不足，主页画布根据实际可用区域选择更小的统一比例并保持居中，不允许只压缩卡片高度。

## 样式与字体

- 应用基础字体从未缩放副本生成，避免重复缩放。
- 平台主题 QSS 每次从原始 QSS 按当前比例生成，不对已缩放字符串再次转换。
- 代码中显式 `setPixelSize`、自绘字体和本地 QSS 必须使用统一比例。
- 移除会覆盖局部已缩放样式的重复样式设置，或保证所有页面只从同一原始主题生成样式。

## 运行时变化

主窗口换屏、屏幕几何变化或逻辑 DPI 变化时：

1. 重新读取目标屏幕逻辑尺寸。
2. 计算新比例。
3. 从基准值重新设置字体、样式和平台控件尺寸。
4. 重新布局居中画布。
5. 比例未变化时不刷新。

禁止在现有值上继续乘比例，防止多次换屏产生累积缩放。

## 验证

- 为比例公式增加无下限截断的单元/源码契约测试。
- 为首页增加契约测试，禁止 `adaptiveHomeModuleCardSize`、`responsiveScaleForSize` 和 `cardScaledInt` 回归。
- 验证标题、卡片、字体、图标、间距只从全局比例获取尺寸。
- 验证 `map_product_manager` 与 `map_product_manager_tools` 没有引入或修改平台缩放代码。
- Release x64 编译通过。
- 人工截图验证 1920×1080、1366×768、1600×900、2560×1440、4K 100%、4K 200% 及至少一种非 16:9 分辨率。
- 在同一分辨率分别打开和关闭日志 Dock，确认构件比例不改变且不存在图标裁切。

## 完成标准

- 1920×1080 保持用户确认的基准视觉。
- 16:9 分辨率下主要平台元素的屏幕占比一致。
- 非 16:9 分辨率等比居中并留白。
- 不存在卡片独立屏幕比例、卡片内部二次比例或硬编码最低缩放阻止整体缩小。
- 平台字体、图标、自绘标题和控件几何同步缩放。
- 插件源码保持不变。
