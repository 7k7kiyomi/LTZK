# 数据裁剪右键入口设计

## 目标

将“地图智能综合”中的“数据裁剪”从插件菜单/工具栏入口移除，改为数据库数据和本地数据图层右键菜单入口。用户右键点击具体图层并选择“数据裁剪”时，复用现有插件加载和动作触发流程，打开原有数据裁剪窗口。

## 范围与约束

- 仅具体数据库表/空间图层、本地图层显示并启用“数据裁剪”。
- 数据库、模式、数据库根节点、文件夹、收藏夹等目录节点不启用该动作。
- 不自动把右键数据重复添加到地图；裁剪窗口沿用插件自身的数据选择行为。
- 不修改插件 DLL；主程序继续通过现有配置绑定、动态加载和 QAction 触发机制调用插件。
- “数据裁剪”不再创建“地图智能综合”菜单动作，也不进入插件栏动作条。

## 设计

### 配置层

`FeatureBinding` 增加 `showInMenu` 字段，默认值为 `true`，保持既有配置兼容。数据裁剪绑定保留插件 ID、模块路径、动作关键字和回退索引，但设置 `showInMenu: false`。这样绑定仍可用于模块权限校验和动作定位，但 `bindPluginFeatureActions()` 不会为它创建菜单 QAction。

### 数据列表层

`DataCatalogWidget` 增加 `DataClipCallback` 和 `setDataClipCallback()`。右键菜单新增“数据裁剪”动作，动作启用条件为 `isCatalogLayer(context)` 且回调已注入；该条件同时覆盖数据库和本地数据树，天然排除目录节点。动作触发时调用回调，不改变现有“添加到地图、刷新、基本信息、导出、重命名”等动作。

### 主窗口层

主窗口创建数据列表后注入回调。回调按 `map_generalization_tools` 和 `数据裁剪` 查找配置绑定，并调用既有 `executePluginFeatureAction()`。该方法继续负责登录校验、DLL 加载、动作关键字/回退索引匹配、错误提示和窗口样式处理，因此右键入口与原插件入口保持同一行为。

## 错误处理

- 配置中找不到目标插件或绑定时，记录警告并弹出“插件动作未找到”提示。
- DLL 加载失败、动作查找失败沿用现有插件错误处理。
- 未登录或无“地图智能综合”权限时，沿用 `ensureAuthenticatedForModule()` 流程，不弹出裁剪窗口。

## 验证

- 静态回归验证 `showInMenu` 解析、数据裁剪配置隐藏、右键动作和图层启用条件。
- 运行现有数据列表、插件绑定和 Release 部署验证脚本。
- 使用 MSBuild 编译 x64 Release，并启动新生成的 Release 程序做冒烟测试。
