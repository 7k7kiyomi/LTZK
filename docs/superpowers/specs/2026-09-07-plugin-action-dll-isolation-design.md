# 插件动作按 DLL 隔离设计

## 目标

修复业务插件已加载后再次点击配置功能时，宿主在所有插件动作中按文字匹配、导致“地图智能综合/接边”误触发“地图成果质检/图幅接边”的问题。

## 已确认根因

`executePluginFeatureAction` 仅在 DLL 首次加载时通过加载前后动作差集得到该 DLL 的动作。DLL 已加载时动作差集为空，现有代码退回全部插件动作；随后 `findConfiguredPluginAction` 按包含关系返回第一个含“接边”的动作，因此会命中先加载的质检插件。

## 方案选择

采用“按 DLL 路径缓存动作归属”的方案：

- DLL 首次加载成功后，只把本次加载新增的、可执行的真实插件动作保存到该 DLL 的缓存项。
- 同一 DLL 后续调用时，只从对应缓存项取动作，禁止退回所有已加载插件动作。
- 缓存使用 Qt 的安全对象指针；动作被插件销毁后自动失效，取出时过滤空指针。
- 配置菜单代理动作（对象名以 `pluginFeature_` 开头）不进入 DLL 动作缓存，防止代理动作再次触发自身。
- 目标动作找不到时保持现有告警并停止，不跨 DLL 猜测或执行其他插件动作。

不采用以下方案：

- 每次卸载并重载 DLL：会丢失插件窗口、任务或内部状态。
- 只把 JSON 关键字改得更具体：依然依赖动作文字，不能从结构上保证插件隔离。

## 数据流

1. 用户点击配置生成的功能按钮。
2. 宿主根据该功能所属 `PluginDefinition.dll` 解析规范 DLL 路径。
3. 若 DLL 尚未加载，记录加载前动作，加载 DLL，再把新增真实动作写入该 DLL 缓存。
4. 若 DLL已经加载，直接读取该 DLL 的缓存动作。
5. 只在这组动作内按 `actionKeywords`、再按 `fallbackActionIndex` 查找目标动作。
6. 找不到则告警并停止；找到才触发。

## 修改范围

- `LTZK.h`：增加按规范 DLL 路径保存动作的缓存成员。
- `LTZK.cpp`：增加真实动作过滤与缓存读写逻辑；删除已加载时退回全局动作池的行为。
- `tests/verify_plugin_action_dll_isolation.ps1`：回归验证缓存按 DLL 分组、禁止全局回退、排除配置代理动作。
- 如项目存在开发包源代码镜像，则同步相同源文件，保持交付包一致。

不修改 `config/plugin_bindings.json` 的菜单名称、关键字和索引。

## 验收标准

- 先后加载质检插件和地图智能综合插件后，多次点击“地图智能综合/接边”，只能从 `plugin_map_generalization.dll` 的动作集合选择。
- 多次点击“地图成果质检/图幅接边检查”，只能从 `plugin_map_quality_check_tools.dll` 的动作集合选择。
- 任一 DLL 的配置关键字或索引无效时，只提示该插件动作未找到，不执行其他 DLL 的动作。
- 新增回归测试、现有插件绑定相关测试和 Release 构建通过。

## 风险控制

- DLL 路径统一使用规范绝对路径并忽略大小写，避免同一 DLL 因路径写法不同产生两个缓存项。
- 不保存失效的 `QAction` 裸指针；触发前再次过滤空指针。
- 不改变插件加载顺序、JSON 格式及现有首次加载行为。
