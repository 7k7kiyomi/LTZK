# 本地数据与数据库成果交互一致性设计

## 目标

本地数据树中的空间文件节点使用与数据库成果图层节点相同的图标和右键菜单结构，并使“按范围导出”“按制图导出”“添加到主题”能够从平台侧调用。数据库成果现有调用链不作改动，本次不修改 `map_product_manager_tools` 插件源码。

## 根因

1. 本地树直接显示 `QgsBrowserProxyModel` 的装饰角色，因此采用 QGIS 浏览器默认图标；数据库成果树使用 `drawProductLayerIcon()`。
2. 本地图层被当作普通叶子节点，数据库中的同类 `.shp` 图层节点则是 `node_type=1` 的目录节点，因此两边进入了不同菜单分支。
3. 菜单启用条件明确写成了 `database && ...`，并且本地分发器只实现了普通导出、添加到地图和目录重命名。
4. 平台没有把本地数据源描述传入成果目录操作，因此三个动作既不能启用，也没有调用参数。

## 设计

- 在本地浏览代理模型中覆盖 `Qt::DecorationRole`：目录复用数据库目录图标，矢量/栅格文件复用数据库成果图标，并缓存矢量几何类型判定结果。
- 本地图层节点采用数据库图层目录节点的完整菜单布局；单个未勾选文件仍以当前右键文件作为操作目标。
- 新增独立的 `LocalProductOperationCallback`。数据库 `ProductOperationCallback`、数据库请求字段和现有 C ABI 全部保持原样。
- 主程序把本地 URI 列表序列化为 `localSources`，通过已有“成果目录操作”隐藏动作交给当前已安装的成果管理插件；含 `localSources` 的请求绕过只支持数据库 ID 的 C ABI，保留完整 QVariant 参数。
- 修改范围严格限制在平台侧 `DataCatalogWidget.h/.cpp` 与 `LTZK.cpp`。

## 安全边界

- 不自动删除、移动或覆盖用户的本地源数据。
- 本地图层菜单中的目录管理操作仍遵循当前本地目录能力；本次只调整用户明确指出的三个灰色动作及菜单/图标一致性。
- 数据库成果请求仍走原来的产品 ID 与连接参数，不添加本地判断，不改变行为。
