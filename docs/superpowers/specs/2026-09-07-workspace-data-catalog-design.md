# 工作区数据列表设计

## 目标

在工作区最左侧增加与“图层管理”并列的“数据列表”。两个入口固定显示在侧边栏底部并可切换；数据列表同时展示当前平台数据库中的可读数据和用户连接的本地文件夹数据。

## 交互结构

- 左侧面板使用底部标签，仅包含“数据列表”和“图层管理”。默认保持“图层管理”，避免改变现有用户习惯。
- “图层管理”页继续承载现有 `QgsLayerTreeView`、工具栏、右键菜单和地图画布桥接，不重新创建图层树。
- “数据列表”页分为“数据库数据”和“本地数据”两个可伸缩区域。
- 数据库区域自动列出当前 `database.ini` 所连接数据库中的非系统 Schema、空间表和普通表。
- 本地区域显示用户已连接的文件夹。用户可连接、断开和刷新文件夹；连接由 QGIS 收藏目录机制持久化。
- 双击可加载的数据项后，将其加入 `QgsProject`。现有图层树桥接负责让新图层自动出现在“图层管理”页。

## 数据边界

- 数据列表表示“可用的数据源”；图层管理表示“当前工程已经加载的图层”。
- 数据库自动加载只读取元数据，不读取整表要素。
- 数据库目录过滤 `pg_catalog`、`information_schema`、PostGIS 拓扑内部 Schema 以及平台权限表 `user_permissions`。
- 本地浏览依赖 `QgsBrowserGuiModel` 的数据项提供器，使 Shapefile 配套文件被组合为一个数据项，并支持 GeoPackage、FileGDB、GeoTIFF 等当前 QGIS/GDAL 能识别的格式。
- 本次不增加网络磁盘、主题管理或服务管理入口；参考图中的这些名称不属于用户请求。

## 组件边界

- `DataCatalogWidget`：数据列表页面、数据库目录、本地目录操作及数据源激活。
- `LTZK`：创建底部双标签，接收数据源激活请求，将矢量或栅格图层加入工程。
- `LTZKAuthManager`：继续负责连接和初始化 `database.ini` 指向的 PostgreSQL/PostGIS 数据库；数据目录复用成功建立的连接，但不承担界面职责。
- `LTZKQgisInterface`：返回真实的 `QgsBrowserGuiModel`，使插件接口与新增数据浏览器保持一致。

## 数据流

1. 工作区构造时初始化本地 QGIS 浏览模型，但默认显示图层管理页。
2. 用户登录成功后刷新数据库目录；首次切换到数据列表时也允许手动刷新。
3. 数据库查询只返回可读表的 Schema、表名、几何列、几何类型和 SRID。
4. 用户连接文件夹后，目录加入 QGIS 收藏并显示在本地数据树中。
5. 双击本地或数据库图层后生成统一的 `QgsMimeDataUtils::Uri`。
6. `LTZK` 根据 URI 创建矢量或栅格图层，检查有效性与重复来源，加入 `QgsProject` 并刷新画布。

## 错误和性能

- 数据库不可用时在数据库树中显示错误节点，并保留本地数据功能和“刷新数据库”操作。
- 本地目录不存在时由浏览模型显示不可用状态，用户可断开后重新连接。
- 数据库目录查询不读取要素；本地目录由 QGIS 数据项模型按展开状态延迟获取子节点。
- 相同 provider 和 source 已经加载时，选中已有图层而不重复添加。
- 加载失败通过现有消息栏和状态栏反馈，不破坏另一个数据区域。

## 验收标准

- 左侧底部出现“数据列表”“图层管理”，默认选中图层管理，切换不重建图层树。
- 登录成功后数据库树列出当前连接数据库中的可读业务数据，并排除系统及权限表。
- 可连接、持久化、刷新和断开本地文件夹；展开时由 QGIS 正确识别 GIS 数据集。
- 双击数据库空间表、本地矢量或栅格后，数据只加载一次并出现在图层管理和地图画布中。
- 数据库断开不影响本地数据浏览。
- 新增回归验证和 Release 构建通过。
