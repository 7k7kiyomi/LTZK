# 数据列表复用菜单栏数据库连接设计

> **已废弃：** 本文记录的“插件向宿主主动桥接连接参数”方案不再采用。当前实现以平台侧读取 `GarMap/MapProductManager` 的 `QSettings` 为准，详见 `2026-09-22-data-catalog-platform-settings-design.md`。

**日期：** 2026-09-22  
**范围：** 主程序数据列表与 `map_product_manager_tools` 菜单栏数据库连接配置之间的连接状态同步

## 1. 目标

- 隐藏数据列表“数据库数据”标题栏中的“连接数据库”按钮。
- 将菜单栏“数据库连接配置”作为数据库数据列表的唯一连接入口。
- 菜单栏连接成功后，数据列表立即显示该连接对应数据库中的数据。
- 菜单栏重新连接其他数据库时，数据列表同步切换到新数据库。
- 菜单栏连接失败、测试连接结束后断开，或数据库断开时，数据列表清空并给出明确提示。
- 保留现有数据库目录查询、成果目录树、本地数据树、右键菜单、双击加载和数据操作回调。

## 2. 当前实现与问题

当前存在两条独立连接路径：

1. `DataCatalogWidget` 自己创建“连接数据库”按钮，通过 `DataCatalogConnectionDialog` 建立 QPSQL 连接，然后调用 `refreshDatabaseData()`。
2. `map_product_manager_tools` 菜单栏的“数据库连接配置”通过 `PostgisConnector` 使用 libpq 建立连接，插件内部成果管理功能使用该连接。

两条路径的数据库参数可能不同，且菜单栏连接成功后主程序数据列表没有状态通知，因此数据列表不能自动跟随菜单栏连接。

## 3. 设计方案

### 3.1 连接状态桥接

在插件侧增加一个轻量桥接方法：

- `PostgisConnector` 暴露当前已连接数据库的主机、端口、数据库、Schema、用户名和密码参数，仅在插件内部组装 `QVariantMap`。
- `CMapProductManagerPlugin` 监听连接状态变化：收到断开状态时通知主程序清空数据列表。
- 菜单栏“数据库连接配置”对话框成功完成连接和 Schema 初始化后，插件主动发送一次最终连接参数，避免在 Schema 初始化完成前刷新一次错误路径。
- 插件自动连接配置完成后也发送一次当前状态，保证启动阶段已有数据库连接时数据列表能够同步。
- 通知通过 `QMetaObject::invokeMethod` 调用主窗口的 `applyMenuDatabaseConnection(QVariantMap)`，使用 Qt 元对象传递，避免主程序链接插件内部类或跨 DLL 传递 `PGconn`。

主程序 `LTZK` 只承担桥接转发：收到参数后转交给 `DataCatalogWidget`。如果菜单栏连接已经断开，传递空参数表示清空状态。

### 3.2 数据列表连接与刷新

`DataCatalogWidget` 增加菜单栏连接同步入口：

- 收到空参数时关闭当前 QPSQL 目录连接，清空数据库模型，显示“请先通过菜单栏‘数据库连接配置’连接数据库”。
- 收到非空参数时先关闭旧的目录连接，再校验主机、端口、数据库和用户名，使用新参数建立 QPSQL 查询连接。
- QPSQL 连接成功后沿用现有 `refreshDatabaseData()` 查询逻辑和成果目录判断逻辑。
- QPSQL 连接失败时不保留旧数据库数据，清空列表并显示同步失败原因。
- `databaseConnectionParameters()` 继续从数据列表当前 QPSQL 连接返回参数，保证导入、成果目录操作等现有回调仍可获得当前数据库参数。

这里的“同一连接”定义为同一组菜单栏连接参数对应的同一数据库；主程序使用独立的 QPSQL 查询连接，不直接使用插件 DLL 内部的 libpq 连接对象。

### 3.3 数据列表界面

- 删除数据列表标题栏“连接数据库”按钮的创建和信号绑定。
- 保留“刷新”按钮，刷新只刷新当前由菜单栏同步得到的数据库连接。
- 不删除旧连接对话框文件，避免扩大本次改动范围；该对话框不再从数据列表界面可达。

## 4. 状态流转

```text
菜单栏打开数据库连接配置
        │
        ├─ 用户取消 ───────────── 保留当前连接和数据列表
        │
        └─ 点击连接
             │
             ├─ 旧连接断开 ─────── 数据列表清空
             │
             ├─ 连接/Schema失败 ── 数据列表保持清空并提示失败
             │
             └─ 连接及Schema成功 ── 传递最终参数
                                      │
                                      └─ 数据列表建立QPSQL查询连接并刷新
```

连接测试沿用现有行为：测试结束后插件连接断开，数据列表收到断开通知并清空；取消菜单栏配置对话框不改变当前已连接状态。

## 5. 错误处理与边界

- 未登录时，数据列表继续显示登录提示，不尝试建立数据库连接。
- 插件连接成功但主程序 QPSQL 驱动或查询连接失败时，只清空数据列表并提示同步失败，不主动断开插件的业务连接。
- 新数据库同步失败时不保留旧数据库树，避免界面显示与当前菜单栏连接不一致的数据。
- 插件或主窗口对象不存在时，桥接通知安全返回，不影响菜单栏数据库功能。
- 不把密码写入新的持久化文件；密码只在当前进程内通过 `QVariantMap` 传递给主程序查询连接。
- 不改变本地数据连接、工作区页签显隐、数据库查询 SQL、产品目录操作和插件业务数据写入逻辑。

## 6. 测试与验收

新增/更新静态回归检查，覆盖：

- 数据列表不再创建或绑定“连接数据库”按钮。
- 数据列表存在菜单栏连接同步入口、空参数清空逻辑和非空参数刷新逻辑。
- 主程序存在元对象桥接槽并转发到数据列表。
- 插件存在连接参数导出、断开通知和连接成功后的最终参数通知。
- 数据列表仍保留现有刷新、数据库树、本地树和业务回调。

验证顺序：

1. 先运行回归脚本，确认新断言在实现前失败。
2. 完成最小实现后重新运行回归脚本。
3. 构建主程序和成果管理插件的 x64 Release 配置，确认新增元对象和跨模块调用编译通过。
4. 进行运行时冒烟检查：菜单栏连接成功后数据列表自动出现对应数据库；重新连接后树内容切换；连接失败或测试断开后列表清空并显示提示。

## 7. 非目标

- 不将插件的 libpq 连接对象直接暴露给主程序。
- 不重写数据库目录查询和成果目录树模型。
- 不保留数据列表中的第二套可操作数据库连接入口。
- 不借此需求重构整个插件加载器或数据库访问层。
