# LTZK 平台新增两种风格设计说明

**状态：** 已获用户确认，待实施

**日期：** 2026-09-01

## 目标

在保留现有“科幻系、黑色系、白色系”及其全部功能、页面内容和业务逻辑的前提下，新增两套可切换、可持久化的视觉主题：

1. **绿色系**（自然野外图册视觉方向；内部 key：`field-notes`）
2. **灰色系**（钢灰暖白视觉方向；内部 key：`steel-warm-white`）

本需求只改变视觉皮肤，不改变页面结构、控件内容、插件绑定、数据处理或算法行为。

## 当前主题架构

- `LTZK.h` 中的 `PlatformTheme` 枚举目前包含 `White`、`Black`、`SciFi`。
- `LTZK.cpp` 通过 `platformThemeKey`、`platformThemeLabel`、`platformThemeFromKey` 管理主题 key、显示名和配置恢复。
- `Resources/styles/ltzk_*.qss` 是三套 QSS 的源文件，`LTZK.qrc` 将它们编译进资源系统。
- `showPlatformThemeDialog()` 提供主题选项，`QSettings` 以 `platform/theme` 保存当前主题。
- 首页背景和部分插件窗口细节由 C++ 自定义绘制或动态样式片段生成，因此不能只增加 QSS 文件，还需要为新 key 增加明确分支。

## 视觉规范

### 绿色系 / Field Notes

定位为长期使用舒适、具有地理工作记录感的浅色主题：

- 纸张底色：`#F4EBD7`
- 森林绿顶部栏：`#3D5540`
- 鼠尾草绿选中态：`#6C7956`
- 地图底色：`#E6DFC5`
- 陶土色强调：`#B86F4F`
- 主文字：`#3E4D3D`
- 视觉语言：柔和圆角、低饱和色、等高线和纸张层次感；不使用科幻霓虹发光。

### 灰色系 / Steel & Warm White

定位为稳定、清晰、偏生产工具的工程工作台：

- 钢灰顶部栏：`#34464B`
- 钢灰侧栏：`#5B6C70`
- 暖白面板：`#F4F2EB`
- 浅灰工作区：`#E4E7E3`
- 标题/品牌色：`#C6D8D2`
- 辅助青灰：`#668B8C`
- 橙色不再作为标题或主品牌色，只用于必要的风险提示、关键状态或操作反馈。
- 视觉语言：直角或小圆角、清晰边界、低装饰密度、工程网格和稳定层级；不使用蓝图霓虹效果。

## 功能与行为要求

- 风格选择窗口从三项扩展为五项，并显示中文名称：科幻系、黑色系、白色系、绿色系、灰色系。
- 选择新主题后立即刷新应用、首页、工作区、插件窗口和动态生成控件的样式。
- 新主题写入 `platform/theme`，应用重启后正确恢复。
- 已有三套主题的 key、QSS、默认值和表现保持不变。
- 非法或未知主题 key 继续回退到科幻系，避免旧配置或外部配置导致启动失败。

## 实现边界

### 需要新增或修改的文件

- 新增：`Resources/styles/ltzk_field_notes.qss`
- 新增：`Resources/styles/ltzk_steel_warm_white.qss`
- 修改：`LTZK.qrc`，注册两套 QSS
- 修改：`LTZK.h`，扩展 `PlatformTheme` 并声明浅色主题分类辅助方法
- 修改：`LTZK.cpp`，扩展主题映射、主题选择、主题持久化恢复、自定义绘制和动态控件样式分支
- 新增：`tests/verify_platform_theme_expansion.ps1`，执行资源、映射、选择项和回归静态检查

### 明确不修改的内容

- 不修改页面布局和业务控件的创建逻辑。
- 不修改插件绑定、数据库、地图数据、算法和结果处理。
- 不修改现有三套 QSS 的视觉规则。
- 不直接修改 `_codex_recovered_*`、`_codex_rollback_*` 或已打包的开发者压缩包；当前源代码根目录是本次实现的唯一源头。

## 验收标准

1. 编译资源时，两套新 QSS 均能通过 `:/LTZK/Resources/styles/...` 读取。
2. “风格选择”窗口可见五个选项，点击新主题后状态栏显示对应中文名称。
3. 重启应用后，`field-notes` 和 `steel-warm-white` 均能正确恢复。
4. 首页、地图画布、工作区面板、表格、树、输入控件、弹窗、插件窗口和动态标题不会错误继承科幻系的深色/发光样式。
5. 现有三套主题的切换和默认科幻系行为不回归。
6. 新增测试脚本通过，且 `LTZK.sln` 编译通过。

## 风险与处理

- **风险：** 当前部分逻辑用“白色 / 黑色 / 其他”隐式区分主题。
  **处理：** 对涉及浅色画布、文本颜色、阴影和内嵌控件的代码改为显式识别新主题，避免新主题落入科幻系默认分支。
- **风险：** QSS 资源已注册但外部运行目录没有对应文件时会回退。
  **处理：** 保持现有资源优先、外部文件其次、科幻系最终回退的读取顺序，并在测试中同时检查资源文件和 QRC 注册。
- **风险：** 自定义首页绘制绕过 QSS。
  **处理：** 在首页背景和顶部绘制逻辑中分别增加两个新 key 的调色分支，保证首页仍属于对应主题。
