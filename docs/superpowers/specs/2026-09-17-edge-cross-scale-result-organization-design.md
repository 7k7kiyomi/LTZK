# 图幅接边与跨比例尺结果组织设计

## 背景

宿主当前会把插件窗口中被识别为输出目录的所有输入框都作为检查结果扫描根目录，并递归加载其中的 `.shp`。图幅接边和跨比例尺窗口还包含“系列图”等中间处理目录，因此中间产物 `merged_index.shp` 被加载并按中间目录名称组织到图层树中。

质检任务管理已有自己的导出逻辑和结果目录约定，本次不修改该逻辑。

## 目标

仅修复“图幅接边检查”和“跨比例尺检查”的结果图层组织：从用户选择的结果输出范围中定位实际的 `<地图名>/质检错误结果` 目录，加载其中的 SHP，并按现有物理目录层级显示严重程度文件夹。已有文件不移动、不复制、不重写。

## 非目标

- 不修改质检任务管理插件的导出代码、导出目录或通用结果扫描行为。
- 不修改图幅接边或跨比例尺插件的 SHP 内容。
- 不把 `merged_index.shp` 转换成质检错误结果；该文件属于中间产物，应被专用结果扫描排除。
- 不依赖 SHP 文件名中的 `error`、`错误` 等关键词来判断结果。

## 方案

在插件绑定中增加可选的结果组织模式，只有图幅接边和跨比例尺两个绑定声明 `mapQualityError`。宿主记录当前绑定的模式；没有该声明的功能继续使用现有通用结果扫描路径。

专用模式保留用户在功能窗口中填写的输出目录作为监控范围，但搜索根目录解析为其中可达的 `质检错误结果` 目录：

1. 若某个用户选择目录本身或其子目录就是 `质检错误结果`，直接把它作为结果根目录。
2. 若用户选择目录是“系列图”等子目录，则向上查找有限层级的共同输出祖先，并在该祖先下定位 `质检错误结果` 目录。
3. 只递归扫描已解析的 `质检错误结果` 根目录；因此地图名和严重程度由实际目录结构自然进入图层树。
4. 专用模式只接受位于解析结果根目录下的 SHP，其他中间目录中的 SHP（包括 `merged_index.shp`）不会被加载。
5. 如果检查完成后结果目录才出现，现有完成后的轮询会重新解析搜索根目录；监控目录仍然使用用户选择的目录。

为避免旧的专用结果层残留，切换到两个功能或重新开始检查时，专用模式的结果注册和树分组仍复用现有安全注册/分组机制；本次只改变专用模式的搜索根和路径归属判断。

## 配置

`FeatureBinding` 增加可选字符串 `resultOrganization`，缺省为空表示通用模式。配置文件仅在以下两个绑定上设置：

```json
"resultOrganization": "mapQualityError"
```

质检任务管理绑定不增加该字段，因此保持现有通用扫描和导出行为。

## 验证

- 静态回归测试确认两个绑定声明专用模式，质检任务管理没有声明专用模式。
- 静态回归测试确认专用搜索根包含 `质检错误结果`，并拒绝其外部/中间目录的 SHP。
- 静态回归测试确认通用 `collectQualityResultSearchRoots()` 分支仍返回原始用户选择目录，且任务管理导出相关代码没有被改动。
- 运行现有质量结果加载、全量重组、双显示和安全树加载测试。
- 重新编译宿主并检查编译输出；运行时用两个功能分别验证图层树路径。
