# 数据目录导入设计

**日期：** 2026-09-09  
**范围：** `DataCatalogWidget` 两棵数据树的右键“导入数据”动作

## 1. 目标

在数据库数据树和本地数据树的右键菜单中增加“导入数据”，但让两类数据走不同的职责边界：

- 数据库节点：只触发现有配置插件的“数据导入”功能。数据目录不负责创建数据库对象，也不验证插件最终是否写入数据库。
- 本地目录节点：采用方案 B，将用户选择的本地 GIS 数据文件复制到右键选中的已连接文件夹，并刷新该文件夹的数据树。

## 2. 交互与启用规则

菜单动作顺序为：

1. 添加到地图
2. 刷新
3. 导入数据
4. 数据裁剪
5. 基本信息
6. 导出数据
7. 批量导出数据
8. 重命名

“导入数据”的启用状态如下：

| 当前节点 | 行为 | 启用条件 |
| --- | --- | --- |
| 数据库根节点、模式节点、空间图层节点、普通表节点 | 触发现有插件“数据导入” | 节点具有数据库身份且主窗口已设置回调 |
| 数据库提示、错误或未登录节点 | 无 | 禁用 |
| 本地已连接文件夹根节点、可浏览的本地目录节点 | 复制本地文件到该目录 | 节点是 `QgsDirectoryItem` 且目录存在 |
| 本地文件、矢量/栅格图层、Favorites 虚拟根节点 | 无 | 禁用 |

数据库动作的显示名称使用“导入数据”，回调内部按现有插件配置查找精确功能名“数据导入”。菜单动作不携带或伪造数据库表名、模式名和写入参数。

## 3. 数据库实现边界

`DataCatalogWidget` 增加无参 `DataImportCallback`。数据库上下文触发该回调后立即返回。`LTZK` 在工作区构造时设置回调：

- 当前工作台为“地图成果管理”时调用 `map_product_manager_tools` 的“数据导入”；
- 当前工作台为“地图智能综合”时调用 `map_generalization_tools` 的“数据导入”；
- 未能识别工作台时默认使用地图成果管理插件。

真正的插件加载、动作查找、输入对话框和数据库导入均继续由 `executeConfiguredPluginFeature()` 负责。数据目录不新增 `QSqlQuery`、DDL、GDAL 数据库写入或数据库对象覆盖逻辑。

## 4. 本地方案 B

1. 右键已连接文件夹或其子目录，点击“导入数据”。
2. 使用 `QFileDialog::getOpenFileNames()` 选择一个或多个本地 GIS 数据文件。
3. 将每个源数据集复制到目标目录；源文件始终保留。
4. 如果目标存在同名文件，自动使用 `_2`、`_3` 等后缀，不覆盖目标文件。
5. 对 Shapefile 及常见栅格辅助文件按同一数据基名复制配套文件，避免只复制 `.shp` 或 `.tif` 主文件造成数据集不完整。
6. 汇总成功、失败和跳过数量；成功或部分成功后刷新目标 `QgsDataItem`，并重新展开目标路径。

Favorites 虚拟根节点不能作为复制目标；本地树的导入只使用 `QgsDirectoryItem::dirPath()`，不调用目录重命名、移动或删除 API。

## 5. 错误处理与安全

- 取消文件选择不产生任何变化。
- 源路径不存在、目标目录不存在、源目标相同、文件复制失败均计入失败汇总，并保留具体路径和错误原因。
- 目标冲突只通过新文件名解决，不覆盖已有本地数据。
- 数据库插件未找到或加载失败由现有插件执行器报告；数据目录不重复弹出“数据库导入成功”提示。
- 保留现有右键菜单中的数据裁剪、导出、批量导出和显示别名边界。

## 6. 代码与测试边界

### `DataCatalogWidget.h/.cpp`

- 增加 `DataImportCallback`、设置器和 `importContextItem()`。
- 增加本地目标目录解析、数据集配套文件收集、冲突路径生成和复制汇总 helper。
- 在统一上下文菜单中加入“导入数据”，数据库和本地分派到不同执行器。
- 本地复制完成后只刷新 QGIS 浏览模型，不改变 `LoadCallback` 和数据库查询协议。

### `LTZK.cpp`

设置数据目录的数据库导入回调，并把插件调用限定为现有配置动作；不新增数据库写入代码。

### `tests/verify_workspace_data_catalog.ps1`

增加静态回归检查：

- 菜单包含“导入数据”，且有 `DataImportCallback` 与导入分派；
- 数据库回调调用 `executeConfiguredPluginFeature` 和配置插件 ID/“数据导入”；
- 本地实现使用 `QFileDialog::getOpenFileNames`、`QFile::copy`、冲突后缀和 `QgsBrowserGuiModel::refresh`；
- 不出现数据库 DDL 或把数据库导入误写成数据目录的 SQL 写入路径。

## 7. 验收标准

1. 数据库节点右键能看到并启用“导入数据”时，只进入现有插件功能；数据目录源码没有数据库写入实现。
2. 本地文件夹节点右键能选择多个数据文件，复制到目标文件夹，遇到重名不覆盖，并刷新目录。
3. 本地源文件、数据库查询、现有数据裁剪和其他右键动作不受影响。
4. 回归脚本通过；若环境允许，x64 Release 构建通过。
