# LTZK 全局分辨率缩放设计

## 1. 目标

以 LTZK 在 Windows、1920×1080 逻辑分辨率下的当前视觉效果作为唯一设计基准。在其他 Windows 逻辑分辨率下，字体、图标、控件尺寸、边距、间距和自绘元素使用同一个比例整体放大或缩小，使界面结构、信息密度和屏幕占比尽量保持一致。

预览中的 1366×768、1600×900、2560×1440、3840×2160 等只是验证样本；正式实现不得维护分辨率白名单，而应连续计算任意逻辑分辨率对应的缩放比例。

## 2. 非目标

- 不通过改变 Windows 系统分辨率或系统缩放实现。
- 不把整个应用渲染成一张位图后再缩放。
- 不对横向和纵向分别拉伸，避免字体、图标和控件变形。
- 不保证不同物理尺寸显示器上的毫米尺寸完全相同。
- 不在本次改造中重做 LTZK 的配色、信息架构或业务流程。

## 3. 基准和坐标定义

### 3.1 基准逻辑分辨率

```text
baseWidth  = 1920
baseHeight = 1080
baseScale  = 1.0
```

缩放计算使用 Qt 高 DPI 体系下 `QScreen::geometry()` 返回的逻辑尺寸，而不是显示器物理像素。这样可自然兼容 Windows 125%、150%、200% 等显示缩放。

示例：3840×2160 物理分辨率配合 Windows 200% 缩放时，Qt 逻辑尺寸接近 1920×1080，LTZK 的应用缩放比例仍应接近 1.0，而不是 2.0。

### 3.2 统一比例

```text
widthScale  = currentLogicalWidth  / 1920
heightScale = currentLogicalHeight / 1080
uiScale     = min(widthScale, heightScale)
```

所有视觉尺寸只使用 `uiScale`，不得分别使用 `widthScale` 和 `heightScale` 拉伸。

默认支持范围建议为：

```text
minimumScale = 0.70
maximumScale = 2.00
```

范围外的显示器仍可运行，但使用边界值；空间不足的窗口通过布局、滚动区和最低尺寸处理。范围值集中配置，测试后允许调整。

## 4. 总体架构

新增一个应用级缩放管理单元，暂定职责名为 `LTZKUiScaleManager`。它是 LTZK 自定义视觉比例的唯一权威来源。

该单元负责：

- 保存 1920×1080 基准尺寸。
- 获取主窗口当前所在的 `QScreen`。
- 根据逻辑屏幕尺寸计算统一比例。
- 提供整数、浮点、尺寸、边距、字体和图标尺寸的转换接口。
- 监听主窗口换屏和屏幕逻辑 DPI/几何尺寸变化。
- 比例变化时发出通知，驱动窗口重新应用视觉规格。

概念接口：

```text
scale()
px(baseValue)
size(baseWidth, baseHeight)
margins(left, top, right, bottom)
fontPixelSize(basePixelSize)
iconSize(baseWidth, baseHeight)
```

应用中不得继续新增页面私有的分辨率比例公式。局部组件可以根据自身可用空间做响应式排列，但其字体和基础视觉尺寸仍来自全局比例。

## 5. Qt 与 Windows DPI 策略

在创建 `QgsApplication` 之前显式启用 Qt 5 的高 DPI 支持和高 DPI 图标支持。Windows DPI 由 Qt 转换成逻辑坐标，LTZK 只在逻辑坐标之上计算分辨率比例。

不使用运行时修改 `QT_SCALE_FACTOR` 作为主要实现手段，原因是：

- 它必须在应用对象创建前确定，不利于窗口运行时换屏。
- 容易与 Windows/Qt 已有 DPI 缩放叠加。
- LTZK 内嵌 QGIS 控件和业务插件，排查双重缩放的成本较高。

应用启动后统一设置基础字体，并通过缩放管理单元调整字体大小。标准控件的公共尺寸可由共享样式和少量应用级样式度量统一管理；业务代码中的固定尺寸仍需逐步接入缩放接口。

## 6. 界面缩放规则

### 6.1 必须同步缩放

- 应用字体和页面专用字体。
- 工具栏、按钮、输入框、组合框和标签的基准高度。
- 图标尺寸。
- 布局边距、控件间距和分组间距。
- 分隔条宽度、圆角、装饰线和自绘元素。
- 对话框的初始尺寸和最小尺寸。
- 自绘控件使用的文字和几何参数。

### 6.2 不应机械固定缩放

以下区域应保留 `Expanding` 布局能力，用来吸收不同宽高比产生的剩余空间：

- QGIS 地图画布。
- 表格和树视图。
- 日志、结果和文本区域。
- 工作区中央内容面板。

固定尺寸只用于确实需要稳定触控面积或视觉比例的控件。大面积内容区域不得改成固定宽高。

### 6.3 字体规则

LTZK 界面字体统一以基准像素大小描述，再乘以全局比例。不得在同一视觉体系中混用未转换的 `pt`、固定 `px` 和系统默认字号。

导出 PDF、打印报表、制图标注等面向输出介质的字体不属于屏幕 UI 缩放范围，继续按照输出 DPI 和版面尺寸计算。

## 7. 不同宽高比

对 16:9 屏幕，整体视觉比例应与 1920×1080 基准基本一致。

对 21:9、16:10、4:3 等屏幕，使用 `min(widthScale, heightScale)` 保证完整显示，不做非等比拉伸。多余空间由地图、表格、树视图等可扩展区域吸收。

例如 2560×1080：

```text
widthScale  = 1.333
heightScale = 1.000
uiScale     = 1.000
```

工具栏、字体和侧栏维持基准尺寸，地图画布获得额外横向空间。

## 8. 多显示器和运行时变化

全局比例以 LTZK 主窗口当前所在屏幕为准。主窗口跨越多个显示器时，以 Qt 判定的窗口所属屏幕为准。

在以下事件发生后重新计算：

- 主窗口首次显示。
- 主窗口移动到另一台显示器。
- 当前显示器逻辑 DPI 变化。
- 当前显示器分辨率或可用几何尺寸变化。

比例未发生有效变化时不得重复刷新。比例变化后统一刷新顶层窗口和已打开对话框，避免部分区域仍使用旧比例。

## 9. 现有代码迁移策略

当前代码已经存在多套局部缩放：

- `visualScaleForWidget()`。
- `topBarScaleForWidget()`。
- `responsiveScaleForSize()`。
- 登录窗口的 `adaptiveScale()`。
- 多个窗口直接使用固定 `resize()`、`setFixedSize()` 和固定 QSS 像素值。

迁移原则：

1. 先建立唯一全局缩放管理单元和基础测试。
2. 将现有公共 `scaledInt()`、`scaledSize()` 转接到全局比例，减少一次性改动。
3. 移除或改造首页、顶部栏和登录窗口各自独立的分辨率比例，防止双重缩放。
4. 迁移主窗口和四个主要业务工作区。
5. 迁移平台自有的认证与权限管理对话框。
6. 搜索并审计平台侧固定字体、固定 QSS 像素、固定尺寸和自绘参数。

`map_product_manager_tools` 及其他业务插件不在本次改造范围内，平台缩放实现不得向插件源码引入 `LTZKUiScale`。

局部卡片根据自身尺寸调整内部排版的逻辑可以保留，但它不得再次代表屏幕分辨率缩放。

## 10. 异常和降级处理

- 无法获得有效屏幕信息时使用 `scale = 1.0`。
- 比例计算结果为非有限值或非正数时使用 `scale = 1.0`。
- 低分辨率下优先启用滚动和布局换行，不继续缩小到最低比例以下。
- 图标优先使用 SVG 或多分辨率资源，避免放大后模糊。
- 缺失指定字体时允许 Qt 使用系统中文 UI 字体回退，但尺寸仍按全局比例计算。

## 11. 验证方案

至少覆盖以下 Windows 逻辑分辨率：

- 1366×768。
- 1600×900。
- 1920×1080，作为黄金基准。
- 2560×1440。
- 3840×2160、Windows 100%。
- 3840×2160、Windows 200%，逻辑尺寸约 1920×1080。
- 2560×1080，验证超宽屏扩展。

每种环境检查：

- 主窗口和首页模块。
- 四个主要业务工作区。
- 登录、权限管理等平台自有对话框。
- 菜单、工具栏、字体、图标和状态栏。
- QGIS 地图画布、图层树和平台属性表。
- 窗口在不同 DPI 显示器之间移动后的刷新。
- 是否存在文字裁切、控件重叠、双重缩放和模糊图标。

自动测试验证比例公式、边界值和尺寸转换；界面测试使用固定场景截图与 1920×1080 基准进行结构和比例对比。

## 12. 完成标准

- 任意受支持逻辑分辨率均通过连续公式计算，无分辨率白名单。
- 1920×1080 下保持当前视觉效果，比例为 1.0。
- 16:9 分辨率下主要控件的屏幕占比保持一致。
- 非 16:9 分辨率不发生横纵变形，多余空间由可扩展内容区域吸收。
- Windows DPI 与 LTZK 分辨率比例不发生双重缩放。
- 主界面和纳入范围的业务对话框不再各自维护屏幕分辨率缩放公式。
- 支持主窗口运行时换屏并重新应用比例。
- 不影响地图坐标、业务数据、打印和导出结果的尺寸语义。
