# 数据目录右键菜单设计

> **后续修订：** 本文原先将“导入”列为非目标；该边界已由 [2026-09-09-data-catalog-import-design.md](2026-09-09-data-catalog-import-design.md) 覆盖。当前实现新增“导入数据”：数据库委托现有插件，本地采用方案 B 复制到选中目录；本文其余右键菜单约束继续有效。

**日期：** 2026-09-08  
**范围：** `DataCatalogWidget` 的数据库数据树与本地数据树

## 1. 目标

为“数据库数据”和“本地数据”两棵目录树提供统一的右键菜单，菜单只包含以下六项：

1. 添加到地图
2. 刷新
3. 基本信息
4. 导出数据
5. 批量导出数据
6. 重命名

菜单需要根据当前节点类型启用或禁用操作，并复用现有的双击加载逻辑。用户能够通过右键菜单完成常用目录操作，而不需要记住双击或工具栏按钮的特殊行为。

## 2. 非目标与安全边界

- 不增加删除目录、新建目录、导入、批量导入等菜单项。
- “重命名”只修改界面显示名称或连接文件夹的显示别名。数据库表名、模式名、数据库对象以及磁盘上的文件名和文件夹名都不能被修改。
- 导出只读源数据，不回写数据库，不覆盖源文件。
- 不改变现有的数据库连接、QGIS 浏览器初始化、收藏夹连接和断开连接行为。

## 3. 现有代码与总体架构

`DataCatalogWidget` 同时拥有两棵树：

- `m_databaseTree` 使用 `QStandardItemModel`。表项通过 `DatabaseLayerTypeRole`、`DatabaseSchemaRole`、`DatabaseTableRole`、`DatabaseGeometryColumnRole` 保存数据库对象信息。
- `m_localTree` 使用 `QgsBrowserProxyModel`，真实对象通过代理索引映射到 `QgsBrowserGuiModel`，再由 `QgsDataItem` 提供 MIME URI、刷新和收藏夹能力。

右键菜单由 `DataCatalogWidget` 统一创建，两个树只负责报告右键位置。菜单处理器先把点击位置设为当前行，然后根据树来源保存一个稳定的上下文（数据库 `QModelIndex` 或本地代理/源索引），最后连接到六个动作处理函数。所有本地索引在调用 QGIS API 前都执行 `mapToSource`，所有显示和选择动作使用代理索引。

菜单动作按“通用动作构建器 + 来源专用执行器”实现：

- 通用构建器负责固定顺序、中文名称、分隔线和启用状态。
- 数据库执行器负责从 `QStandardItem` 角色构建 `QgsMimeDataUtils::Uri`。
- 本地执行器负责从 `QgsDataItem` 的 `mimeUris()`、`children()`、`refresh()` 和 `QgsFavoritesItem::renameFavorite()` 取得或更新数据。

## 4. 节点与动作启用矩阵

| 当前节点 | 添加到地图 | 刷新 | 基本信息 | 导出数据 | 批量导出数据 | 重命名 |
| --- | --- | --- | --- | --- | --- | --- |
| 数据库根节点 | 禁用 | 启用 | 启用 | 禁用 | 启用 | 启用 |
| 数据库模式节点 | 禁用 | 启用 | 启用 | 禁用 | 启用 | 启用 |
| 数据库矢量/栅格图层 | 启用 | 启用 | 启用 | 启用 | 禁用 | 启用 |
| 数据库普通表、提示行 | 禁用 | 视节点而定 | 启用（提示行禁用） | 禁用 | 禁用 | 禁用 |
| 本地已连接文件夹根节点 | 禁用 | 启用 | 启用 | 禁用 | 启用 | 启用 |
| 本地目录节点 | 禁用 | 启用 | 启用 | 禁用 | 启用 | 禁用 |
| 本地矢量/栅格图层节点 | 启用 | 启用 | 启用 | 启用 | 禁用 | 禁用 |
| 无效、加载中或提示节点 | 禁用 | 禁用 | 禁用 | 禁用 | 禁用 | 禁用 |

目录节点的“批量导出数据”只导出当前节点已加载的后代图层；如果后代尚未由 QGIS 浏览器加载，处理器先请求 `fetchMore`/刷新，随后在当前事件循环中重新收集。仍未加载的子树不会被伪造为文件，结果对话框会明确报告“未加载或不支持”的数量，提示用户展开或刷新后重试。

## 5. 六个动作的详细行为

### 5.1 添加到地图

- 数据库图层：复用现有 `activateDatabaseItem()` 的连接参数和 URI 构建逻辑，通过 `m_loadCallback` 加载矢量或栅格图层。
- 本地图层：复用现有 `activateLocalItem()`，读取 `QgsDataItem::mimeUris()`，只提交 `vector` 和 `raster` URI。
- 目录、模式、根节点和普通表不执行加载，也不弹出误导性的成功提示。
- 没有加载回调时动作保持禁用，避免菜单点击后静默无响应。

### 5.2 刷新

- 数据库任意可刷新的目录或图层都执行 `refreshDatabaseData()`，重新读取目录和空间元数据，并保留本次会话中的数据库显示别名。
- 本地节点映射到源索引后调用 `QgsBrowserGuiModel::refresh(sourceIndex)`；刷新结束后重新绑定 Favorites 根节点和代理树，保持当前显示结构。
- 刷新期间状态标签显示“正在刷新…”，失败时通过状态标签或消息框报告错误，不清空已存在的有效目录直到新结果准备好。

### 5.3 基本信息

使用只读信息对话框（`QMessageBox` 文本区即可）显示：显示名称、来源类型、提供者、路径或数据源 URI，以及可取得的模式、表名、几何列、几何类型、SRID、文件大小和最后修改时间。数据库信息来自 item roles 和当前连接；本地信息来自 `QgsDataItem`、MIME URI 和 `QFileInfo`。信息展示不触发写操作。

### 5.4 导出数据

单个矢量或栅格图层先弹出保存文件对话框，过滤器由 QGIS writer API 提供：

- 矢量：使用 `QgsVectorFileWriter::fileFilterString()` 和 `writeAsVectorFormatV3()`。根据目标扩展名选择驱动，默认文件名沿用显示名称并清理 Windows 非法字符。
- 栅格：默认 GeoTIFF（`.tif`），使用 `QgsRasterLayer` 创建 `QgsRasterPipe`，再由 `QgsRasterFileWriter::writeRaster()` 写出。
- 数据库和本地 URI 都走同一组 writer helper；解析 URI 产生的临时图层由 `owner` 标志控制释放。
- 成功后报告输出路径；失败后报告 writer 返回的完整错误文本。源文件不会被移动、重命名或删除。

### 5.5 批量导出数据

对数据库根节点、模式节点或本地文件夹节点执行：

1. 弹出一次输出目录选择框。
2. 递归收集当前节点下已加载的矢量/栅格 URI。
3. 为每个矢量图层生成独立的 GeoPackage 文件，为每个栅格图层生成独立的 GeoTIFF 文件；文件基名来自源数据名，遇到重名追加 `_2`、`_3` 等后缀。
4. 汇总成功、失败和未加载/不支持的数量，并列出失败原因。

这样可以支持同一目录下混合矢量和栅格数据，同时避免把多个不兼容的 provider URI 强行写入一个容器。批量导出只作用于输出目录中的新文件，不改变原始目录结构。

### 5.6 重命名（仅显示别名）

- 数据库根节点、模式节点和图层允许输入新的显示文本。文本保存于 `DataCatalogWidget` 的内存别名表，键由数据库名、模式名、表名、图层类型和数据列组成；刷新目录时重新应用别名。任何数据库 URI、表名、模式名和 SQL 都继续使用原始角色值。
- 本地只允许重命名 Favorites 下的“已连接文件夹根节点”。调用 `QgsFavoritesItem::renameFavorite(dirPath, newName)` 更新 QGIS Favorites 显示别名；传入的物理 `dirPath` 不变，因此磁盘目录名不变。普通子目录和文件节点不提供重命名，避免误触发物理文件系统改名。
- 输入为空、与当前名称相同或包含换行时不保存，并给出简短提示。取消对话框不产生任何变化。

## 6. 代码改动边界

### `DataCatalogWidget.h`

- 增加数据库别名哈希表。
- 增加右键菜单入口、动作处理器、URI 构建、信息收集、单个/批量导出和别名重命名的私有声明。
- 保留现有双击、连接、断开和刷新接口不变。

### `DataCatalogWidget.cpp`

- 为两个树设置 `Qt::CustomContextMenu` 并连接 `customContextMenuRequested`。
- 新增通用菜单构建和数据库/本地上下文解析。
- 抽取数据库 URI 构建，使双击和“添加到地图”共享一份代码。
- 新增 vector/raster writer helper、批量递归收集 helper 和只读基本信息展示。
- 在数据库目录重建时应用内存别名；在本地 Favorites 根节点使用 QGIS 别名 API。
- 不修改 `LTZK.cpp` 的地图加载回调协议。

### `tests/verify_workspace_data_catalog.ps1`

增加静态回归检查，验证：

- 两棵树都启用自定义右键菜单并连接处理器。
- 六个中文动作名称全部存在，删除/新建/导入菜单名称不存在。
- 添加到地图调用现有加载回调，刷新分别连接数据库和本地刷新路径。
- 导出代码使用 QGIS vector/raster writer，批量导出和显示别名 helper 存在。
- 本地重命名使用 `renameFavorite`，数据库重命名只写入 alias map，不出现修改表名或物理文件名的调用。

## 7. 验证与验收标准

1. 静态验证脚本通过，且没有新增编译警告导致的失败。
2. x64 Release 配置成功编译，输出的 `LTZK.exe` 能正常启动。
3. 数据库连接后：右键数据库根/模式/图层时动作启用状态符合矩阵；“添加到地图”与双击结果一致。
4. 连接本地文件夹后：右键文件夹根节点可以刷新、查看信息、批量导出和修改显示别名；重新刷新或重新打开软件时磁盘路径仍保持不变。
5. 对单个矢量、单个栅格和混合目录分别执行导出，成功/失败统计和文件扩展名正确。
6. 右键菜单不出现未确认的删除、新建、导入等操作，普通数据库表不会被当作可加载图层。

## 8. 已知限制

- 本次数据库显示别名默认只在当前 `DataCatalogWidget` 会话内保存，避免把 UI 别名误写入数据库或全局配置；重新启动后数据库目录恢复原始对象名。
- 本地批量导出依赖 QGIS 浏览器当前已加载的子节点。状态报告会区分“未加载/不支持”，用户可先展开或刷新目录再重试。
- 导出目标若已存在，使用 Qt/QGIS 的标准覆盖确认；任何覆盖只可能发生在用户明确选定的输出文件，不会影响源数据。
