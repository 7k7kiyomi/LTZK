# 质检结果输出目录识别设计

## 目标

修复结果面板依赖目录名称的缺陷。用户把质检输出目录命名为“输出结果”“测试”或任意其他名称时，结果面板都应从本次质检使用的输出目录中发现并显示输出 SHP。

## 根因

当前 `collectQualityResultSearchRoots()` 从所有插件窗口的 `QLineEdit` 中查找目录，但只有目录名包含 `result`、`error`、`信息` 或 `结果` 时才接受；没有命中时还会回退到工程文件目录和输入图层目录。这样“测试”目录会被排除，输入目录也可能被误扫。

## 方案

1. 在质检动作开始时清空上一轮结果目录状态，并记录当前插件窗口中对象名包含 `output` 的目录型路径控件。
2. 在质检动作执行后和定时同步期间，从当前可见插件窗口读取这些输出路径控件；将路径规范化为绝对路径，并更新本次质检记录的输出目录。
3. `collectQualityResultSearchRoots()` 只返回这些记录的输出目录及其子目录，不再调用目录名称关键词判断，也不再从工程文件或输入图层目录推导扫描根目录。
4. 既然扫描根目录已经由用户选择的输出目录限定，扫描其中的 SHP 时不再要求文件名包含 `error`、`err` 或固定中文目录名；输出目录下的有效 SHP 均可进入结果面板。
5. 保留现有的规范化路径去重、扫描时间窗口、文件数/图层数上限、结果图层注册表和结果面板显示逻辑。

## 数据流与边界

- 质检插件窗口不存在或没有有效目录型路径时，不扫描工程目录、输入图层目录或当前工作目录，结果面板显示“未发现质检输出 shp”。
- 输入路径控件（例如 `lineEdit_InputDataPath`）不参与结果目录收集；输出路径控件通过控件对象名中的 `output` 标识识别。
- 输出目录名称不参与任何业务判断。
- 输出目录下的子目录继续递归扫描。
- 每次质检动作重置扫描起始时间和输出目录记录，并通过文件修改时间过滤上一次动作的旧 SHP。
- 结果 SHP 仍以 registry-only 图层加入 QGIS，并由结果面板控制地图显示，不加入可见图层树。

## 测试策略

新增静态回归检查，验证：

- `collectQualityResultSearchRoots()` 不再使用目录名关键词函数；
- 不再使用工程/输入图层目录作为 fallback；
- 质检动作开始时重置路径记录，动作后和定时扫描前从对象名含 `output` 的用户路径控件收集输出目录；
- 任意目录名下的 SHP 都能进入结果扫描，而不是依赖 `error` 文件名；
- 原有结果面板 registry-only、扫描时机、分组显示和行数上限检查继续通过。
