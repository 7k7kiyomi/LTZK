# 图层关系配置下拉框文字显示修复设计

## 背景与根因

图层关系配置窗口中的 `QComboBox` 已由插件设置了当前显示文字，但宿主程序随后会统一接管下拉框，将其设为可编辑并重新配置内部 `QLineEdit`。在这段二次润色过程中，当前文字可能未被保留到内部编辑框，导致只看到下拉箭头而看不到已匹配的图层名称。

现有的单元格文字抑制逻辑只负责避免 `QTreeWidgetItem` 背景文字与嵌入控件重复绘制，不应移除或改写。问题也不归因于三套主题的文字颜色。

## 目标与范围

- 在宿主 `LTZK.cpp` 的图层关系下拉框润色函数中，保存下拉框已有的 `currentText()`。
- 完成 `setEditable`、内部 `QLineEdit` 样式、字体、调色板和边距设置后，将保存的文字恢复到内部 `QLineEdit`。
- 覆盖白色、黑色和科幻主题，因为三套主题共用这条宿主处理路径。
- 保留现有 CSV 图层匹配、无效图层过滤、单元格背景文字隐藏和下拉箭头处理逻辑。
- 增加源码级回归检查，验证保存发生在 `setEditable(true)` 之前，恢复发生在内部编辑框样式设置之后。

## 非目标

- 不修改 `Drawing_Layout` 插件的 CSV 解析或图层匹配逻辑。
- 不通过修改 QSS 颜色或字体来掩盖问题。
- 不改变空值下拉框的语义；如果原始 `currentText()` 为空，修复不会凭空生成文字。

## 方案与数据流

在 `polishDrawingLayoutTreeEmbeddedCombos` 的 `polishCombo` 闭包内：

1. 读取 `combo->currentText()`，保存为局部字符串。
2. 执行现有的可编辑状态、控件字体、样式表、调色板、边距和箭头配置。
3. 确认内部 `lineEdit()` 存在后，将非空的保存文字写回 `combo->lineEdit()`。
4. 保持现有的刷新调用，使恢复后的文字立即参与绘制。

恢复只针对非空原始文字执行，避免把真正的空值变成错误显示；恢复操作放在内部编辑框样式和调色板设置之后，确保后续控件接管不会覆盖恢复结果。

## 错误处理与兼容性

- 若 `combo` 为空，沿用现有直接返回逻辑。
- 若 `lineEdit()` 为空，沿用现有条件保护，不执行恢复。
- 只保存和恢复显示文本，不改变下拉框选项、当前索引或信号行为。
- 现有按主题生成的颜色和箭头资源逻辑保持不变。

## 验证

- 先运行回归检查，确认当前实现因缺少保存/恢复逻辑而失败。
- 完成最小代码修改后重新运行同一检查，确认通过。
- 运行相关的表格嵌入控件检查；若本机具备完整 Qt/Visual Studio 构建环境，再执行 Debug 或 Release 构建并检查退出码。
- 最终复核差异，确保只涉及目标实现和回归检查，不包含无关改动。
