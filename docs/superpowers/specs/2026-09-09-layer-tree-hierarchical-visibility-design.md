# 图层管理父子勾选联动设计

## 背景

图层管理使用 QGIS 的 `QgsLayerTreeView` 和 `QgsLayerTreeModel` 展示地图、质检结果组及其下属目录/图层。当前模型虽然已经启用 QGIS 的层级可见性标志，但实际运行中父节点勾选变化仍可能只更新父节点，导致界面勾选状态与实际地图显示状态不一致。

## 目标

为图层管理启用层级勾选语义：

1. 取消任意父组时，递归取消该组下全部子组和图层。
2. 勾选任意父组时，递归勾选该组下全部子组和图层。
3. 单独修改子图层后，父组根据子节点状态显示全选、未选或半选状态。
4. 继续通过现有 `dataChanged` 信号刷新地图画布，不改变结果面板和结果 SHP 自动加载逻辑。
5. 普通图层、地图目录和质检结果目录统一遵循同一套父子联动规则。

## 方案

在 `LTZK::initLayerTreeView()` 中使用应用侧的 `LTZKLayerTreeModel` 子类，并继续启用 QGIS 已提供的 `QgsLayerTreeModel::ActionHierarchical` 标志。子类只重写 `setData()` 的复选框处理：先调用 QGIS 基类逻辑，再判断被操作节点是否为组节点；如果组的子树状态仍未与目标状态一致，则调用 `setItemVisibilityCheckedRecursive()` 进行兜底同步。子图层单独勾选不会进入组节点分支，因此不会把同级图层误关掉。

现有的 `refreshMapCanvasLayerStack()` 保持不变，仍监听模型数据变化并根据图层树状态刷新地图。这样父组取消后，子图层会先由模型同步为未选，再由现有地图刷新逻辑移出画布；重新勾选父组时则反向恢复显示。

## 边界与兼容性

- 只修改图层树模型行为，不修改结果面板的 `QTreeWidget`。
- 不改变图层分组、结果 SHP 注册、结果面板详情或文件夹组织逻辑。
- 不在 `dataChanged` 回调中做递归修改，避免信号递归或状态覆盖。
- 组节点只在复选框操作成功后做状态校验，已同步的子树不会重复写入。
- 依赖当前工程使用的 QGIS 版本已提供 `ActionHierarchical`，该接口已在本地 QGIS 头文件中确认存在。

## 验收标准

- 源码配置检查能确认 `ActionHierarchical` 与 `AllowNodeChangeVisibility` 同时启用。
- 源码检查能确认图层树使用 `LTZKLayerTreeModel` 的组节点递归兜底。
- 编译通过，且不引入新的编译错误。
- 用户取消“永登县30w”时，其所有子目录和图层复选框同步取消。
- 用户取消“质检错误结果”时，其下所有结果 SHP 图层复选框同步取消。
- 父组和子图层状态变化后，地图画布显示状态与图层树一致。
