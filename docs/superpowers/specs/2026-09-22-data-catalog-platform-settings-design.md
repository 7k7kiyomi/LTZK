# 数据列表平台侧读取菜单数据库配置设计

**日期：** 2026-09-22  
**范围：** `LTZK` 宿主的数据列表，不修改 `map_product_manager_tools` 源码

## 1. 目标

- 隐藏数据列表自身的“连接数据库”入口，保留数据列表的“刷新”入口。
- 菜单栏数据库配置成功保存后，数据列表自动显示该配置对应数据库中的数据。
- 菜单栏重新保存另一组连接配置后，数据列表关闭旧的 QPSQL 查询连接并切换到新数据库。
- 数据列表继续使用现有目录查询、成果目录树、本地数据树和右键操作逻辑。
- 插件只保留原有连接与设置保存逻辑，不添加任何宿主桥接代码。

## 2. 根因

菜单插件使用 `QSettings("GarMap", "MapProductManager")` 保存：

```text
db/host
db/port
db/database
db/schema
db/user
db/password
db/savePassword
```

宿主数据列表原来只拥有自己的 QPSQL 连接，并等待插件主动发送参数；插件连接成功后没有宿主可接收的通知，因此列表仍显示“请先通过菜单栏连接数据库”。两边使用的是同一台数据库，但没有状态同步路径。

## 3. 方案

### 3.1 宿主侧设置读取

`DataCatalogWidget` 使用同一组组织名和应用名读取菜单插件的设置。主机、端口、数据库和用户名缺失或端口无效时返回空配置；Schema 为空时按 `public` 处理。密码不保存到新的文件或成员变量；它只从现有设置读取并立即交给 QPSQL 建立查询连接。

配置字段按固定顺序生成 SHA-256 指纹，成员变量只保存指纹，不保存明文密码。指纹包括密码，因此用户修改密码或重新勾选“记住密码”也会触发重新连接。

### 3.2 同步时机

数据列表构造完成后启动 500 ms 定时器，并执行一次延迟初始检查。每次检查：

1. 未登录时不建立宿主查询连接；登录成功后原有 `refreshDatabaseData()` 会强制触发同步。
2. 设置指纹变化时，调用现有 `applyMenuDatabaseConnection()`。
3. 指纹未变化且 QPSQL 查询连接有效时，不重连、不重复加载。
4. 数据列表刷新按钮调用强制同步；连接曾失败或已丢失时可以重试。
5. 设置中没有保存密码时清空宿主列表并提示用户在菜单栏勾选“记住密码”后重新连接。因为不修改插件，宿主无法读取插件进程内未持久化的密码。

### 3.3 刷新职责拆分

原 `refreshDatabaseData()` 中的数据库目录查询主体移动为私有 `loadDatabaseData()`：

- `refreshDatabaseData()` 先同步菜单设置，再调用加载主体。
- `applyMenuDatabaseConnection()` 成功建立 QPSQL 连接后直接调用 `loadDatabaseData()`。

这样既支持定时同步，也避免 `applyMenuDatabaseConnection()` 与 `refreshDatabaseData()` 互相递归。

## 4. 状态与错误处理

- 新配置连接成功：清理旧模型，建立 QPSQL 连接，按现有逻辑显示数据库、Schema、表和成果目录。
- 新配置连接失败：不保留旧树，显示“菜单栏数据库连接同步失败”及数据库错误。
- 配置没有密码：不尝试空密码连接，清空模型并给出明确提示。
- 注销：沿用宿主现有 `applyMenuDatabaseConnection(QVariantMap())` 清理查询连接和模型。
- 菜单插件连接失败但没有保存新配置时，宿主无法从 `QSettings` 判断插件内存中的断开状态；宿主只会继续使用上一份成功保存的配置。这是“不修改插件源码”方案的边界。

## 5. 测试与验收

- 平台侧静态契约测试检查 QSettings 键、定时轮询、指纹、未保存密码提示和非递归刷新入口。
- 工作区数据列表回归测试继续检查未登录保护、数据库树和本地树集成。
- Release x64 只构建宿主 `LTZK`，不构建插件。
- 运行验收：登录平台后，菜单栏连接并保存配置，等待不超过一个轮询周期，数据列表出现对应数据库数据；修改菜单配置并成功保存后列表切换；未保存密码时显示提示。

## 6. 非目标

- 不修改 `map_product_manager_tools` 的任何源文件或 DLL。
- 不让宿主链接或传递插件内部的 `PGconn`/`PostgisConnector` 对象。
- 不重写数据库目录 SQL、成果目录模型、本地目录逻辑或插件加载流程。
